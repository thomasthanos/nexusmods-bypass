## 🐛 Reporting a bug

Use the <a href="https://github.com/thomasthanos/nexusmods-bypass/issues/new/choose"><kbd>📝 Guided Issue Form ↗</kbd></a> and include:

- **Extension version**
- **Browser** and browser version
- **Collection or download mode** involved
- **What you expected**
- **What happened instead**
- **The generated error report**, when available

> [!CAUTION]
> **Do not include** Nexus credentials, cookies, tokens, or private URLs.

## 🔧 Sending a pull request

1. **Fork the repository** and create a focused branch.
2. **Make the smallest change** that solves the problem.
3. **Load `src/` as an unpacked extension** and exercise the affected flow.
   - **In Firefox:** Load the built `dist/nexus.mods.bypass-<version>-firefox.zip` instead — `src/manifest.json` declares a `background.service_worker`, which Firefox does not accept; the Firefox manifest is generated by `tools/build-zip.mjs`.
4. **Run the locale validator** when strings change. It fails on a missing or extra key, a placeholder a translation drops or points at another argument, a key defined twice, a key no code uses, and a store name or description over the Chrome Web Store limits:

   ```bash
   node tools/check-locales.mjs
   ```

5. **Run the package builder** before submitting. It runs the locale check and every regression suite in `tests/unit/` and `relay/test/` first, up to four at a time (`NXTK_TEST_JOBS=1` runs them one by one), and packages nothing unless they all pass; the same gate runs on every push:

   ```bash
   node tools/build-zip.mjs
   ```

   A new `*-test.mjs` file in `tests/unit/` or `relay/test/` goes into `CHECKS` in `tools/build-zip.mjs` (the gate refuses a test it does not run) and ends by printing a line with `OK`: a test that exits without it is treated as one that stopped half-way.
6. **Playwright tests** (`npm run test:visual`) start the browser through `tests/visual/helpers.mjs`, which keeps it offline, and wait for states rather than for time; lint refuses `waitForTimeout`.
7. **Explain** what changed and how it was tested.

> [!IMPORTANT]
> Keep permissions narrow, **do not** add remote code or telemetry, and **do not** commit generated archives from `dist/`.
