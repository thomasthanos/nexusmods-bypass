# 3.1.4 — Reliable error reporting and Discord delivery

Error reports now survive the failures they are meant to describe. The extension no longer stalls on very long diagnostic text: report redaction used to backtrack quadratically, and 100 KB without whitespace blocked the page or the background worker for 15–28 seconds. Only a bounded head of each text is scanned now, and a token cut at that boundary is dropped whole instead of being kept half redacted. User-facing messages in the error log are redacted and length-limited like every other field.

A fault that repeats in a tight loop, such as a callback failing on every page update, reaches the background log at most once every two seconds and at most 20 times a minute from one page or the worker. Grouping and counting in the error log are unchanged.

The report page no longer reads every HTTP 503 as "the report server is not set up": only the relay's own answer means that, and a temporary outage offers a retry. HTTP-date `Retry-After` values are understood, and the automatic-report queue waits out a `Retry-After` on 503 as it already did on 429. A damaged entry in the stored queue is dropped instead of stopping delivery.

The Cloudflare relay gains a shared Discord dispatcher (`relay/discord.js`). It waits out Discord rate limits using Discord's own `retry_after` plus jitter, retries gateway errors and network failures with bounded backoff, and never retries a message Discord rejected. A longer limit is passed to the extension as `429` with Discord's `Retry-After`. Every unexpected failure is answered with CORS headers instead of an opaque 500. A KV failure falls back to memory instead of refusing the report, and bookkeeping after a delivery can no longer cause a duplicate post. Undeliverable reports are written to the Worker log as one secret-free line, and e-mail remains the fallback when configured. Embed text is clipped without splitting emoji. Crashes and bug reports are red (`#ED4245`); other automatic faults are amber (`#E8B339`).

GitHub release, issue, manifest and schema notices use the same dispatcher instead of `curl`, keeping the webhook off the command line. A failed post is a workflow warning, never a failed job.

Chrome and Firefox packages use 3.1.4 with the same permissions. The relay update is deployed separately with `npx wrangler deploy` from `relay/`; the existing 3.1.2 Worker stays compatible with this release until then. No live Discord test messages were sent; every delivery path is covered by offline tests.
