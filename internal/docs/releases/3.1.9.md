## 3.1.9 — Straight to Vortex

**Mod Manager Download** reaches Vortex again where it stopped with "The request to Nexus Mods could not be completed", collection files are named like single downloads, and Mod Organizer 2 users can have a `.meta` file saved beside each one. Both browser ZIPs are under **Assets**.

- **Mod Manager Download fixed:** on some mods the button ended with a network error since 3.1.7, although Nexus itself was answering. The extension now opens Nexus's download link the way the button itself does, and the browser hands it to Vortex. When Nexus says no (sign in, access denied, file not found, too many requests, a browser check), you see that answer instead. Reported in [#30](https://github.com/thomasthanos/nexusmods-bypass/issues/30).
- **Collections carry on:** a collection run that meets such a file fails just that file and goes on, instead of waiting about 17 minutes for a connection that works.
- **Collection file names:** files from a collection get the same name as a single download: the name in Nexus's download link, otherwise *mod name-file id*.
- **Mod Organizer 2 `.meta` files:** a new setting, *Write Mod Organizer 2 .meta files* (off by default, under **Collections**), saves a `.meta` file with the mod's Nexus ID, file ID and version beside each collection file saved in the browser.
- **Busy buttons:** *Download all mods* (and the mandatory and optional buttons) shows a spinner and stays disabled until the download panel opens.
- **Saved data kept safe:** if the browser fails to read stored data, the extension no longer writes defaults over your settings, history or queue.

<summary><strong>Repository & reports</strong> — what changed behind the scenes</summary>

- Automatic reports leave out what is not a fault: Cloudflare or error pages at a mod's address, a Nexus notice in place of the download button, a collection's retried attempts, and requests Firefox cancels as a page changes. A "no link" report says what kind of link or notice Nexus answered with.
- The relay accepts at most 500 reports an hour from everyone together, on top of 10 per IP. Its baseline moves to 3.1.9, and the tests check it against the manifest; both take effect once the Worker is redeployed.
- A live Nexus schema check that fails no longer stops a release; the weekly schema watch still reports it.
- Extension permissions are unchanged. Automatic reports remain off unless you turn them on.
