# 3.1.5 — Waiting out lost connections, and a Vortex hand-off that follows Vortex's rules

A collection run no longer falls apart when the connection drops. Before, a request to Nexus that got no answer at all counted as that file's failure: three quick retries, then the next file, which failed the same way, so a one-minute Wi-Fi drop failed every remaining file within seconds, each with its own error dialog. Both the background queue (browser downloads) and the Vortex run in the page now wait on the same file instead, with a countdown that says it is the connection and not a rate limit. The waits grow from 30 seconds to 5 minutes, about 17 minutes in all (in the page they also end early when the browser reports it is online again), and only when they have run out does the run stop, with one error. Completed files stay in history, so starting again continues where it stopped. A link request that gets no answer while the file's page did answer is still that request's own failure.

Errors are classified by what they are. Only a request that got no answer is a connection problem; a bug in the extension used to read "check your connection" and would now have been waited out as an outage, so it is reported as a failed request instead, and an abort nobody timed is a cancel, not "took too long".

Firefox numbers downloads afresh in every browser session and gives the downloads it reloads no owner. After a restart, the id a running queue had saved could therefore name an unrelated download: a finished one was counted as the collection's file, and Stop could cancel or delete it. The queue now keeps the path of the link its own download came from (without the query string) and never counts, resumes, cancels or deletes a download that came from another link; its own download is treated as lost and gets a fresh try.

A full disk, or a download folder the browser cannot write to, stops the run on that file with a clear message instead of asking Nexus for a link for every remaining file and failing each one. Download paths drop the characters Chrome refuses in a file or folder name, which failed those files as "Invalid filename".

The Vortex hand-off was checked against Vortex's open-source handling of `nxm://` links:

- Vortex hands an incoming link only to the download waiting for the same game, mod and file id; any other link starts a separate download and leaves the waiting one parked. The extension now only takes, and only hands off, a link that names the file it asked for.
- Vortex comes to the front only when its *Bring Vortex to foreground when starting downloads in browser* setting is on, and a browser that opens `nxm://` links without asking shows no prompt. Silence after a hand-off is therefore no longer counted as "Vortex did not open"; only focus returning after the prompt, or the user's own answer, counts. Before, every hand-off with that setting off counted as a failure, the tab Vortex opened stayed open, and browser downloads were offered while every file was arriving in Vortex.
- A hand-off from a tab that was already in the background used to count as "Vortex opened", closing the tab and remembering Vortex as working. It is now unknown.
- A link that reaches a Vortex which is still starting is dropped, and only the link that starts Vortex is safe. The second file of a run waits 20 seconds after the first hand-off.
- Vortex refuses a link signed for another Nexus account. The "Vortex didn't open?" hint now names that, next to the nxm:// handler and the browser prompt.
- The *Test Vortex* link (`nxm://premium`) only re-reads the membership in a Vortex that is already running and does not bring it forward. The test explains that, and a "No" no longer counts as a failed hand-off.

On the page, the click that the hint asks for is no longer dropped as a duplicate for 15 seconds; a Vortex link that could not be found no longer hands the same file's Manual download to Nexus's slow flow; overlapping downloads keep their own error details and "Sent to Vortex" state; Pause also holds a Vortex run after a skipped or failed file; "Retry failed" on the summary works after a run that was stopped, blocked or needed a sign-in; a collection deck that Nexus re-renders during a Vortex run gets its progress, Stop and Pause back; and a run shows one error dialog instead of one per failed file.

Reports say more and leak nothing: a download that ends without a link lists what each Nexus request answered (its HTTP status, how long a failed request took, and the shape of the answer, never its text or the link), two different unhandled rejections are no longer merged into one entry, and report URL fields never carry secrets.

Chrome and Firefox packages use 3.1.5 with the same permissions. The relay gains two report titles (`no_nmm_link`, `popup_error`) that need `npx wrangler deploy` from `relay/`; the deployed Worker keeps working with this release until then.
