## 3.1.7 — The right file for Vortex and Mod Organizer 2

Vortex and Mod Organizer 2 get the link for the file you asked for again, and the reports that reach the maintainer are the ones someone can act on. Both browser ZIPs are under **Assets**.

- **The right file:** Nexus's download dialog now names a file by its uid (the game id × 2³² plus the file id). The extension read that uid as the file id, asked Nexus for a file that does not exist, and then refused the correct `nxm://` link as another file's: "the nxm link names another file", the most frequent report from 3.1.5 and 3.1.6. Clicks, dialogs, the collection deck and the final Vortex check now read either form.
- **Pages fetched as a click loads them:** the Vortex page, the requirements page and the download API are requested the way a click requests them, so Nexus answers with the full page and its `nxm://` link instead of a tab fragment without one.
- **Clearer messages:** a collection that Nexus is moderating, has hidden or cannot find says so, in all 13 languages, instead of "Unexpected response · Refresh the page". Closing or leaving a tab mid-request is a cancel, not a network error.

<details>
<summary><strong>Reports & privacy</strong> — what changed in automatic reports</summary>

- A request cut off by closing or navigating the tab is not reported or logged. Connection failures of the mod-files list, mod details and game lookup, which the page works without, stay in the local debug log.
- An unavailable collection stays local, like other ordinary conditions.
- Report text no longer hides ordinary words after "mod", "file", "game" or "collection" ("Loading mod files" used to arrive as "Loading mod [id]"). Ids, game domains and slugs are still masked.
- When a Nexus page no longer looks as expected, the report describes its structure: the newer or older Nexus layout, whether it has a main region and a heading, up to three custom elements and fixed test hooks, roughly how much text, and the kind of title. Never the text, the title or an identifier. Next.js's own 404 page is not counted as a site change. [PRIVACY.md](https://github.com/thomasthanos/nexusmods-bypass/blob/main/PRIVACY.md) lists these fields.
- The relay pings the maintainer only for manual bug reports and for automatic errors from 3.1.7 or newer; warnings and older versions' reports are still delivered, without a ping. This takes effect once the relay Worker is redeployed, and reports keep arriving until then.
- Extension permissions are unchanged. Automatic reports remain off unless you turn them on.
