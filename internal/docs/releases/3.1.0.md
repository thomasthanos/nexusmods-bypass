### Updated downloads — 14 October 2026

The ZIPs in this existing **3.1.0 release** have been replaced with builds of extension **3.1.1**. Install these updated ZIPs to receive the fixes below. The release tag remains `3.1.0`; the updated extension source is <a href="https://github.com/thomasthanos/nexusmods-bypass/commit/05f2a657deecff20d5be36177ed365f68202edbb"><kbd>05f2a65</kbd></a>.

- **One-click error reporting:** a one-time invitation on Nexus Mods lets you enable technical reports directly in the page, without an extra browser permission or another confirmation tab. Choosing No thanks, Escape or no action keeps automatic reporting off.
- **Accessible invitation:** clearer Greek/English text, keyboard and screen-reader support, larger buttons, visible focus and scrolling at higher zoom.
- **Fewer lost errors:** background and collection failures use a persistent queue with retries, timeouts and per-error grouping. New faults can send immediately; ordinary login/offline/cancellation/rate-limit conditions stay local. Turning reports off clears pending reports.
- **Better manual reports:** Add details opens the selected incident, with a stable error reference shared by the dialog and diagnostics. Manual reports keep their reviewed JSON attachment.

The richer Discord formatting and separate relay rate limits are prepared in the source but require a separate Cloudflare Worker deployment. That deployment is not included in this ZIP refresh.

---

Better feedback when sending files to Vortex, easier setup and settings, and quieter error reports. This release brings together **15 commits**, including the starting commit, from `fc33a049` through `4d91769`.

### At a glance

- **Know what happened:** separate Vortex delivery history, useful recovery actions and collection summaries.
- **Set up without the clutter:** three presets, compact settings and clearer explanations in all 13 languages.
- **Less UI friction:** smoother info panels, raised popup buttons and a stable settings shortcut.
- **Cleaner diagnostics:** readable time estimates and one compact Discord embed for automatic errors.

<details>
<summary><strong>Vortex & downloads</strong> — delivery feedback, history and recovery</summary>

- Files sent to Vortex are tracked separately from browser downloads. Sending a link is no longer treated as proof that Vortex finished downloading it; missing files can be resent, with Vortex handling files it already has.
- The first collection delivery checks for Vortex opening and asks when it cannot tell. A positive answer is remembered per browser profile; a failed delivery or a “No” makes the check available again.
- Cancelling the browser's “Open Vortex?” prompt no longer counts as success. Focus polling and page interaction help detect the cancellation; a failed delivery cancels the pending tab close so recovery remains accessible.
- Every Vortex delivery shows “Sending to Vortex…” and “Sent to Vortex”, including auto-start file pages without a download button. The real Nexus button label updates without replacing its icon, even after a page re-render.
- If Vortex does not appear to open, single-file downloads offer a helpful hint. After two consecutive failures, collection downloads offer browser downloads and the Vortex installation guide.
- Expired `nxm://` links are checked with a 30-second safety margin and fetched again once. Collection feedback identifies the account the links were signed for and warns when it differs from the page account.
- Requirement skipping supports Nexus's native download buttons, JSON file attributes and nested open shadow roots. Download-link generation is attempted before loading a complete file page.
- Native Close/Cancel buttons and Escape are no longer intercepted as download actions. The extension's own dialogs and toasts are also excluded from download-click interception; `nmm=0` is not treated as a Vortex request.
- Whole-collection guidance explains when to start the collection in Vortex and use the extension for the files Vortex requests. Completion messages say “sent”, not “downloaded”.

</details>

<details>
<summary><strong>Collections & activity</strong> — useful estimates, summaries and fewer interruptions</summary>

- Remaining time uses localized, human-readable units such as `3h 12m`. The estimate smooths per-file latency and large-file throughput separately, with configured speed as a fallback.
- Completed activity lines include file size; runs crossing midnight show a date. Adopted browser runs use the worker's correct file metadata and do not invent an ETA.
- Chrome and Edge can suppress the browser download bubble during browser collection runs. It is restored on completion, stop, failure or extension reload/update; Vortex runs do not suppress it. Repeated checks are coalesced.
- Both browser and Vortex runs end with sent/downloaded, skipped and failed totals. Skips include reasons; recovery offers **Retry failed**, **Copy list** and **Open failed pages** (up to 10).
- Browser retries queue only failed files. Collection history distinguishes **Sent to Vortex**, **Downloaded** and **Not downloaded yet**, with **Resend missing** and **Clear history**.
- Rate-limit feedback appears only when the queue actually waits, and the server's retry delay survives link resolution. Collection menu actions run after the menu closes and show failures instead of silently doing nothing.
- Removed or unavailable file pages offer **Open the Files tab**. Genuine page-layout changes get a plain-language warning; technical selector details stay in the diagnostic report.

</details>

<details>
<summary><strong>Setup, settings & popup</strong> — compact, clearer and keyboard-friendly</summary>

- First-run setup asks about Vortex/browser downloads, the browser download folder and closing the extra tab. **Test Vortex** uses the harmless `nxm://premium` link and asks for confirmation when needed.
- **Vortex user**, **Browser downloads** and **Minimal** presets update live; mixed choices show **Custom**. Applying a preset updates the current dialog instead of replacing it, and does not change pacing settings.
- Settings use naturally sized Downloads, Collections and Appearance groups, with six technical options under a collapsed Advanced section. Two balanced columns become one on narrow screens; header/footer stay visible while the content scrolls.
- Switches sit beside their labels. Short descriptions stay visible; full explanations open through accessible info buttons, including touch and keyboard use. All 13 languages receive clearer settings text and Vortex feedback.
- Explanations animate when opening **and** closing, handle rapid reversals and return to natural height after settling. Reduced-motion preferences disable the movement.
- Saves run in order, so a later manual edit wins over an in-flight preset. Failed saves show a warning and restore the previous value; closing waits for pending saves.
- Reset waits for pending writes and requires confirmation. A failed reset keeps the dialog open without reloading; Cancel/Escape restore focus to the reset control.
- The popup uses raised glass actions, clearer Help & Bugs buttons and visible keyboard focus. **Report on GitHub** opens an issue; only an oversized report needs the clipboard fallback.
- **Page settings** opens the active Nexus tab's panel or a Nexus page with the settings deep link. Troubleshooting uses stable current/legacy anchors and an expanded Quick fixes section.
- The settings shortcut stays hidden behind extension dialogs and conflicting Nexus menus, including menus inside open shadow roots. It avoids real download controls, adapts at narrow widths/high zoom, and no longer resets its visible position while scrolling.

</details>

<details>
<summary><strong>Errors & reports</strong> — clearer next steps, less duplication</summary>

- Error dialogs offer relevant actions: **Sign in**, **Open file page**, **Use browser download**, or a rate-limit countdown that becomes **Retry now**.
- Automatic Discord errors arrive as one compact embed, without a duplicate JSON attachment. Known errors use plain-language explanations; page/action context stays readable, with a short browser name and compact version/error/HTTP/report-ID metadata.
- Manual bug reports retain their full JSON attachment. Existing rate limits, duplicate suppression, redaction and mention protections remain in place.
- Vortex activity and error debug lines are saved immediately rather than waiting for the normal batch. Pending log entries flush when the page is hidden or left, reducing lost diagnostics when a temporary tab closes.

</details>

<summary><strong>Compatibility & verification</strong> — permissions, packages and coverage</summary>

- **Chrome / Edge:** the optional collection download-bubble setting uses the additional `downloads.ui` permission. **Firefox:** that permission is omitted; the release ZIP is unsigned and supports temporary loading in Firefox 140+.
- Vortex must be running and signed into the same Nexus account. The browser can confirm that a link was sent, not that Vortex finished downloading it.
- This commit range adds regression coverage for queue estimates, file parsing, protocol prompts, settings saves/reset, report formatting, keyboard/focus behavior, long translations, higher zoom and menu/control overlap. It also includes large-queue/history and worker-restart scenarios.
- The replacement 3.1.1 ZIPs passed the regression/build gate and Firefox package lint (0 errors). The complete Chromium layout suite passed in GitHub Actions for the packaged source; additional local checks verified ordinary CORS in Chromium and Firefox without host permissions. The release tag remains 3.1.0, and the updated package source is linked above.
