## 3.3.6 — Queue recovery and precise retries

This patch adds regression coverage for browser recovery, collection summaries and Wabbajack history identity.

- **Recovery without duplicate downloads:** after a worker restart, an unreadable browser download list no longer means that a pending transfer is absent. The start marker is kept and checked again before another copy can start.
- **Restarting after Stop:** a successful cancellation callback no longer clears the retirement barrier when the browser cannot confirm the download's resulting state. A readable follow-up can release the wait normally.
- **Collection summary retries:** files with identical archive names are matched by their queue position and file identity, so Retry and the file-page link refer to the failed file. Reconnected queues do not invent retry targets from ambiguous names.
- **Wabbajack history:** distinct non-Latin titles sharing a year, and long titles sharing the same prefix, now receive separate history keys. Ordinary ASCII keys are preserved, as are canonically equivalent Unicode spellings. Previously ambiguous titles receive new keys; their existing downloads may need history reimport. Stored history is not deleted or migrated.
- **API fallback failures:** a router HTTP 403, Cloudflare verification or access-denied response is preserved when the earlier v2 response contains an error instead of usable data.

Extension permissions and reporting opt-ins are unchanged.

The live report relay's comparison baseline is 3.3.6. Existing bindings and secrets are preserved.
