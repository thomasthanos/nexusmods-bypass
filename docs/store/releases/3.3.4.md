## 3.3.4 — Firefox startup and download recovery

This patch improves Firefox startup, resolves trusted Nexus download routes and gives slow-rendering mod pages another bounded check before reporting a site change.

- **Firefox startup:** if a loaded page has no body yet, the extension waits for it and then starts. Requirements-tab and Files-tab handling no longer fail while the body is absent.
- **Trusted download routes:** when Nexus supplies its own download route instead of a usable direct link, manual Vortex clicks, one automatic Vortex attempt and browser collection queues can use the verified route for the requested file and game. Routes for another file or game are refused.
- **Collection pacing and restart:** skipped or unavailable files leave a gap before the next request, with a longer pause after a Cloudflare response. Firefox can restart a stopped run once the browser confirms its previous download no longer exists; an unreadable download list still prevents overlapping runs.
- **Slow mod pages:** a Nexus shell with navigation controls but no mod content gets one additional bounded render check. A page whose content stays missing still reports the failure.
- **Queue refusals:** waiting for a previous download to finish retiring remains a safety refusal, with its state returned to the caller, and is no longer recorded as a critical extension crash.

These changes do not bypass antivirus checks, browser security, Cloudflare verification, or Nexus sign-in and availability notices. The cause of the supplied network-failure report remains unproven; this patch does not claim to fix it. Extension permissions are unchanged.

The relay's extension-version baseline is 3.3.4 and takes effect when that Worker is deployed.
